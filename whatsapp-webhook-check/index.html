WhatsApp Webhook Check

Dashboard test events reach your server, real customer messages do not, and the Graph API answers with error 100, subcode 33. This small script finds which of the usual causes it is, using read-only requests.

Download wa-check.mjs Source and tests

What it checks

  1. App not subscribed to the WABA. Subscribing to the messages field in the App Dashboard is not enough, the app also needs POST /{waba-id}/subscribed_apps. Without it only test events arrive.
  2. Token without access to the WABA. A System User token that is not assigned to this WhatsApp account, or lacks whatsapp_business_management, gets error 100/33 on GET /{waba-id}.
  3. Callback override. An override on the WABA or on one phone number, often left over from a previous provider, sends events to another URL.
  4. Number not on Cloud API, or app in Development mode. The first is checked from platform_type, the second is a reminder because the token cannot read it.

How to run

Node.js 18 or newer. The token stays on your machine: it is read from an environment variable, used only for GET requests to graph.facebook.com, and never printed. Nothing in your setup is changed; when a fix is needed the script prints the command for you to run.

export WA_TOKEN="your system user token"
export WABA_ID="WhatsApp Business Account ID"
export PHONE_NUMBER_ID="optional, to check one number"
export APP_ID="optional, to confirm it is your app that is subscribed"
node wa-check.mjs

On Windows PowerShell use $env:WA_TOKEN="..." instead of export. Graph API version defaults to v23.0, set GRAPH_VERSION to change it.

Example output

From the test suite with mocked Graph API responses, not a real account.

[OK  ] Token is valid and has both WhatsApp permissions
[OK  ] WABA reachable: Sample Delivery Co
[FAIL] No app is subscribed to this WABA
       The webhook field subscription in the App Dashboard is not enough: the app also has to be subscribed to the WABA, otherwise only dashboard test events arrive.
       Fix: curl -X POST "https://graph.facebook.com/v23.0/104857600000001/subscribed_apps" -H "Authorization: Bearer $WA_TOKEN"
[WARN] +1 555 010 0199 (Sample Delivery) has a callback override
       Effective callback: https://old-provider.example/webhook
       Fix: If this URL is not yours (often a previous provider), remove or replace the override for this number only.
[INFO] Check App Mode by hand
       App Dashboard top bar: the app should be Live. In Development mode only dashboard test events are delivered.
